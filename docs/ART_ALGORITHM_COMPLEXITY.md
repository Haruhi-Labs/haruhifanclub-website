# 画廊算法复杂度盘点

本文覆盖画廊前端 `apps/art`、后端 `backend/crates/server/src/modules/art.rs`、
`art_guild.rs` 及画廊数据库索引。普通字段映射、表单校验和常数规模枚举不单独列项。

## 记号

- `n`：当前作品集合大小；`k`：本次追加的作品数；`c`：瀑布流列数（当前最多 5）。
- `p`：输出图片像素数；`t`：单件作品的标签/文本 token 数。
- `N`：满足查询条件的全站作品数；`E`：全站浏览、点赞、评论事件数。
- `C`：推荐候选数（当前最多 5000）；`H`：推荐历史数（当前最多 5000）；`L`：返回数（当前最多 24）。
- `q`：公会一次提交的作品数（当前最多 60）；`u`：唯一用户/创作者数。
- `P`：空间背景粒子数；`P_g`：第 `g` 组粒子数；`F`：框体数；`M`：弹性网格节点与边总数。

## 前端

| 路径 | 时间复杂度 | 空间复杂度 | 结论 |
| --- | --- | --- | --- |
| Squoosh WebP 压缩、Canvas 缩放 | `O(p)` | `O(p)` | 像素级工作不可避免；编码已放在 Worker，传输使用 transferable，主线程不复制像素缓冲区。 |
| 图片比例探测 | `O(n + Σp)` | `O(n)` 加浏览器解码内存 | 已优化：比例完成后原位更新数组，去掉每张图一次的整数组复制；仅看 JS 数组操作由累计 `O(n²)` 降为 `O(n)`。 |
| 推荐画廊增量瀑布流 | 首次/换列 `O(nc)`；追加 `O(kc)` | `O(n+c)` | 已优化：追加只计算新作品并复用旧列；此前每批都会复制全部历史列，连续加载会累计到二次量级。 |
| 画廊批次去重与追加 | `O(k)` 去重和追加 | `O(n)` | 已优化：持久 `Set` 保存作品 ID，并就地追加响应式数组；此前每批重建历史 ID 集并复制历史数组。 |
| 两行平衡布局 | `O(n)` | `O(n)` | 已优化：使用比例前缀和；此前每个切分点重复 `slice + reduce`，为 `O(n²)`。 |
| 普通 justified / 双列 / 随机行布局 | `O(n)` | `O(n)` | 保留；行内候选数和末两行修正规模都有上限。 |
| 创作者卡片瀑布布局 | `O(nc + Σ作品数)` | `O(n+c)` | 线性重排；响应式计算在追加时会重算，但创作者接口分页且每卡最多 4 件作品。 |
| 曝光追踪 | Observer 回调 `O(k)` | `O(n)` | `Set/Map/WeakMap` 均摊 `O(1)`；定时器只为可见卡片创建。 |
| 推荐事件队列 | 入队均摊 `O(1)`；上报 `O(b)` | `O(b)` | `b≤40`，有固定上限。 |
| 3D 空间背景每帧 | `O(Σ P_g² + F log F + M)` | 场景 `O(P+F+M)`，帧内额外 `O(1)` | 已优化：只在同组粒子中检查连线，桌面端候选对从 2016 降至 261；复用投影/排序缓存并预渲染粒子与字形。移动端关闭连线并限为 30 FPS，持续掉帧时才降低 DPR 与模糊半径。 |
| 后台/兑换页本地筛选 | `O(n·文本长度)` | `O(n)` | 数据由后端限制/分页，当前没有嵌套全量扫描热点。 |

## 后端公开画廊

| 路径 | 时间复杂度 | 空间复杂度 | 结论 |
| --- | --- | --- | --- |
| 最新/普通列表 SQL | 索引定位后约 `O(log N + pageSize)`；深页另含 `OFFSET` 成本 | `O(pageSize)` | 已有状态、来源、作者、时间复合索引。极深分页仍建议未来改游标。 |
| 稳定随机分页 | `O(log N + offset + pageSize)`，另有分段计数 | `O(pageSize)` | 使用持久 `random_key` 和索引，避免 `ORDER BY RANDOM()` 的 `O(N log N)`。 |
| 全局人气榜 | `O(N + E + N log N)` | `O(N)` | 为保证按完整 Wilson/互动分数精确全局排序，仍需全量排名；这是保留的主要重路径。 |
| 限定作品人气统计 | `O(r log r + E_r)` | `O(r)` | 已优化：普通列表、详情、相关推荐和个人展位只查询实际消费的作品 ID，并按 500 个 ID 分块；此前这些请求也会扫描全站 `E` 条互动。 |
| 单作品详情 | 应用层 `O(1)`；数据库按作品 ID/互动索引查询 | `O(1)` | 已从全站人气扫描降为单 ID 统计。 |
| 个性化推荐 | `O(E + Ht + Ct + LC)` | `O(N+H+C)` | `C,H≤5000`、`L≤24`，选择循环因此实际近似线性；全局人气统计仍是主要成本。 |
| 相关推荐 | `O(Ct + E_C + C log C)` | `O(Ct)` | `C≤1000`；已将人气读取从全站 `E` 限定为候选互动 `E_C`。 |
| 相关文本 token 化 | `O(字符数)` | `O(token 数)` | 中文双字 token 和 ASCII 段均为单次扫描。 |
| 创作者信息流 | `O(N + E + Σ m_i log m_i)` | `O(N)` | 仍会为稳定随机作者顺序和质量归一读取全量个人作品；是数据继续增长后的优先优化候选。 |
| 创作者展位 | `O(N + E + Σ m_i log m_i)` | `O(N)` | 默认展位需全局人气；显式展位可在未来拆成更轻查询。 |
| 账号显示名批量映射 | `O(n log n + u)` | `O(u)` | 已优化：先排序去重账号 ID，再按 500 个 ID 分块，避免同一作者多作品造成重复 SQL 参数并规避绑定参数上限。 |
| 图片尺寸补全 | 缓存命中 `O(n)`；未命中为 `O(n)` 次图片头读取 | `O(n)` | 只读图片头，不解码整图；有进程缓存和上限。 |
| 缩略图生成 | 约 `O(p)` | libvips 流水线有界 | 尺寸白名单、磁盘缓存、并发闸为 2；热路径由 nginx 静态直出。 |

## 后端公会与后台

| 路径 | 时间复杂度 / 查询次数 | 结论 |
| --- | --- | --- |
| 投稿 ID 去重 | `O(q)` | 已优化：用 `HashSet` 保序去重；此前 `Vec::contains` 为 `O(q²)`。 |
| 委托/访问许可作品合法性校验 | `O(q)`，1 次读取查询 | 已优化：一次 `IN` 查询返回合法 ID；此前最多 60 次串行查询。 |
| 委托作品写入 | `O(q)`，1 次批量写入查询 | 已优化：事务内生成多值 `INSERT`；此前最多 60 次串行写入。 |
| 后台访问许可申请作品回填 | `O(总作品 ID 数)`，每 500 个 ID 一次查询 | 已优化：跨最多 200 条申请统一预取并按原顺序回填；此前为“申请数 × 每申请作品数”的 N+1 查询。 |
| 社交卡片、徽章、昵称 | `O(u)`，批量 `IN` 查询 | 已是批量路径，无逐用户查询。 |
| 排行榜 | 数据库聚合/排序约 `O(G + 流水数 + G log G)` | 结果只返回前 50，但“我的排名”要求保留完整排序结果。 |
| 活跃委托刷新与任务列表 | `O(Q)` 应用循环，最坏仍有 `O(Q)` 次索引查询 | 活跃任务数当前很小；若任务规模明显增长，应批量预取 claims/progress，消除剩余 N+1。 |

## 本轮收益与后续门槛

本轮优先消除了会随画廊增长放大的累计 `O(n²)` 前端复制、无关请求的全站互动扫描，
以及公会批量操作中的串行 N+1。保留的全局重路径都有明确语义原因或硬上限。

建议在以下任一条件出现时进入下一轮：

1. 已审核作品接近 5,000，推荐候选开始稳定触顶；
2. 互动表达到百万行，完整人气统计 P95 明显上升；
3. 创作者信息流 P95 超过 300ms；
4. 活跃公会委托达到数十条。

下一轮应优先考虑物化作品互动计数/时间窗汇总、创作者信息流缓存，以及基于游标的深页分页。
